# MIGRATION PLAN

Goal: independent Next.js + Prisma + local PostgreSQL product. Base44 export is a read-only reference.

## 1. Guardrails
- Do not modify or delete anything in the Base44 tree (`src/`, `base44/`, root `package.json`, configs). No `reference/` directory exists; the export stays where it is. Proposal: leave in place now, optionally `git`-snapshot first (see risks), then move to `reference/base44-export/` only on your approval.
- All new work goes in `jokzet-command-center/` (existing scaffold). No Base44 SDK import, no Supabase.
- No deployment without approval. No invented learning URLs: video fields stay empty/"to be supplied" until real links are given.

## 2. Recommended architecture

- **Next 16 App Router, TypeScript strict**, React 19, server components by default, server actions + route handlers for mutations. (The scaffold's `AGENTS.md` warns APIs differ from older Next: read `node_modules/next/dist/docs/` before coding.)
- **Tailwind 4 + shadcn/ui + lucide + Recharts + Zod**.
- **Prisma + PostgreSQL 16** (local). Normalised schema (below).
- **Auth**: own implementation. Argon2id (`@node-rs/argon2`) hashes, random 256-bit session tokens stored hashed in `Session` table, httpOnly+SameSite=Lax+Secure cookie, CSRF via origin check plus server actions, login rate limiting, generic error messages, password policy. No localStorage tokens. (Auth.js considered; custom DB sessions chosen for full control and fewer moving parts. Revisit if you prefer a library.)
- **Authorization**: one data-access layer (`lib/data/*`) where every query takes `userId`; no raw client-provided ownership; `requireUser()` on every action/route.
- **Storage abstraction**: `StorageProvider { put, getStream, delete }`; `LocalDiskStorage` writing outside `public/` to `storage/` (gitignored); downloads via authorised route handler; MIME sniff + extension allow-list + size caps + random keys; S3-compatible driver later.
- **Time**: `date-fns` + `date-fns-tz`, stored UTC, displayed Africa/Accra. Schedule: Mon FSD, Tue UX, Wed Security, Thu Cloud/SysAdmin, Fri AI/Biz, Sat Photo/Video, Sun review. Programme start 2026-11-16 (a Monday). Reminder 12:00 default.
- **Reminders/notifications**: in-app notifications generated by a scheduled job (node-cron or an API route invoked by OS scheduler); email/push optional later.
- **Testing**: Vitest (unit), integration tests against a separate test database, Playwright for E2E/responsive; ESLint, `tsc --noEmit`, `next build` in a `check` script.

## 3. Data model (Prisma, normalised)
`User, Profile, Session, Department, LearningPath, Level, Skill, Mission, MissionStep, Resource, RubricCriterion (AssessmentRubric), LearnerMission (status, saved progress, startedAt), Submission, SubmissionFile, Assessment, AssessmentScore, Feedback, UserSkill, Achievement, UserAchievement, ActivityRecord, Reminder, Notification, PortfolioProject, CapstoneProject, CapstoneMilestone` plus BusinessOS tables in Phase 9 (`Product, StockMovement, Customer, Supplier, Sale, SaleItem, Expense, ...` all owner-scoped).
Curriculum (departments, levels, skills, missions, rubrics) is seed data (`prisma/seed`), idempotent, all learners start at Level 0. XP/level are derived from passed assessments in a server transaction, never from the client.

## 7. Risks and missing information
1. **No PostgreSQL available** – need your go-ahead to install (installer, or Docker Desktop) and a choice of port/credentials.
2. **The ZIP and `reference/` directory do not exist**; export is unpacked at root. Confirm the root Base44 files are the intended reference.
3. **No git** – no rollback. Recommend `git init` and an initial commit (will ask first).
4. **Curriculum content is absent.** Missions, rubrics, passing scores, remediation and demos must be authored. Video demonstrations: no real URLs supplied, so missions will carry "demonstration to be added" placeholders (clearly labelled) unless you provide approved sources.
5. **Scope is very large** (~25 models, 9 departments of content, BusinessOS ERP). Phase 6 content volume is the main schedule risk; suggest authoring Level 0–1 only per department first.
6. **Auth scope:** do you need password reset by email, MFA or social login at launch? Single learner or multi-user? (Affects email provider and role model.)
7. **Programme date logic:** programme start is 16 Nov 2026 (5 days from today, 11 Nov 2026). Confirm Sunday-review and missed-day/catch-up behaviour.
8. **Level/XP rules** (300/900 XP in Base44) – keep, or define pass-based progression?
9. **Next 16.4.6 / React 19.3 / Tailwind 4.3.3** are in the scaffold; docs in `node_modules` must be consulted before coding.
10. Windows environment: file-storage path handling, Argon2 native binaries and line-ending issues need checking early.
